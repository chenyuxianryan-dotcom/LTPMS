**版本**：v1.0
**作者**：陈煜贤
**日期**：2026-09-22
**状态**：草稿
**产品类型**：内部工具（实验实训管理系统 LTPMS）

## 1. 背景与目标

### 1.1 背景

智能查询（ASY-01 检索终端，`/nlq`）当前只接受文字输入，而师生要查询的问题和要录入的数据大量存在于纸面与实物上：纸质课表、打印的实验指导书、黑板通知、仪器屏幕截图。5 Why 分析显示「智能查询使用率低」的根因是**入口只接受文字**——用户必须先把现实世界的信息自己翻译成文字提问，这一步拦住了大部分使用意愿。

系统已具备全部积木：三条查询链路（NL2SQL 取数、我的档案 Agent、知识库顾问作答）、一条视觉识别通道（课表照片→结构化行，现挂在课表导入场景）、文件上传的校验与落盘机制。当前是「已有积木的新组合」而非新工程，边际成本低。不做的后果：识图能力继续孤立在课表导入一个场景里，智能查询停留在"会打字的人才能用"。

### 1.2 目标用户

| 用户角色 | 特征描述 | 核心诉求 | 使用场景 |
|---------|---------|---------|---------|
| 学生 | 实验中遇到问题，手边只有纸质指导书/实物 | 不打字也能问「这页讲的操作是什么」「我这周哪天没课」 | 实验课中，拍指导书某页/拍纸质课表贴进终端 |
| 教师 | 带多个班，纸质签到表/考试安排常更新 | 拍表即查，识别结果可确认写入系统 | 排课季，拍纸质考试安排查询空闲时段 |
| 管理员 | 负责课表/知识库数据维护 | 收到黑板通知、打印表格截图后可快速提取并录入 | 开学周，通知类图片批量转文字 |

### 1.3 业务目标与成功指标

| 目标 | 衡量指标 | 目标值 | 监测方式 |
|------|---------|--------|---------|
| 降低提问门槛 | 含图片的查询占智能查询总请求比 | 上线 4 周 ≥ 10%（基线 [待补充]） | 埋点 `nlq_image_submit` |
| 识别结果可直接用 | 草稿确认写回成功率（写回成功数/草稿确认数） | ≥ 90% | 埋点 `nlq_draft_confirm_result` |
| 兜底不误导 | 低置信度图片走「没看清」兜底而非硬答的比例 | 100%（人工抽检 30 例） | 抽检 + 埋点 `nlq_vision_low_confidence` |
| 通道收敛 | 智谱视觉通道调用次数 | 归 0（下线验证） | 服务日志 |
| 现状基线 | 智能查询周活跃用户数、周请求数 | [待补充] | 现有查询历史表统计 |

## 2. 需求概述

在智能查询终端增加图片附件入口，系统自动识别图片意图并分流：文档类走顾问作答（带出处），表格类先转结构化再查询并产出可确认写入的草稿。

## 3. 功能详细设计

> 角色口径：以下「查询」均受现有数据权限注入约束（教师见本人相关、管理员见全量），图片不扩大任何人的数据可见范围。

### 3.1 F1 附图输入能力（P0）

**功能描述**：智能查询终端输入区支持附带一张图片提交查询。
**用户故事**：作为学生，我希望把图片贴进检索终端并配一句话提问，以便不用把纸面内容手动转成文字。
**优先级**：P0

**业务规则**：
1. 单次查询最多 1 张图片；支持三种添加方式：粘贴（Ctrl+V）、拖拽、点击选择文件。
2. 格式白名单 jpg/png/webp，单张 ≤ 10MB，服务端按"扩展名+内容魔数"双重校验（与现有头像/知识库上传同口径）。
3. 允许"纯图无文字"提交（配文可选），此时系统按 F3 自动推断意图并在结果中说明理解到的问题。
4. 图片缩略图在输入区可见、可移除；提交后输入区清空。
5. 悬浮问答组件（NlqWidget）本期不提供附图入口，仅 `/nlq` 全屏终端支持（范围控制，来源：批次规划）。

**交互流程**：
1. 用户从 `/nlq` 终端输入区添加图片 → 显示缩略图+文件名+移除按钮
2. 可选输入配文 → Ctrl+Enter 提交
3. 成功：结果区先展示「图片理解摘要」（系统看到的图片内容概述），再展示对应链路的回答
4. 失败：格式/大小不符 → 提交前即拦截并提示具体原因（"仅支持 jpg/png/webp，当前文件 xxx.pdf"）

**异常处理**：

| 异常场景 | 处理方式 | 用户提示 |
|---------|---------|---------|
| 图片损坏/无法解码 | 拒绝提交 | 「图片无法读取，请重新拍摄或导出」 |
| 提交中途网络失败 | 图片与配文保留在输入区可重试 | 「提交失败，已为你保留内容」 |
| 视觉服务超时/不可用 | 整次查询失败，不降级为盲答 | 「识图服务暂不可用，你可以改用文字描述提问」 |
| 10MB 边缘大图中途压缩失败 | 原图直传，不压缩（服务端限制兜底） | 同格式校验提示 |

### 3.2 F2 识图通道统一（P0）

**功能描述**：系统内所有图片识别使用同一个具备图像理解能力的模型通道（deepseek-flash），现有智谱视觉通道下线。
**用户故事**：作为管理员维护者，我希望识图与查询共用一个模型账号和降级策略，以便配置、限流、成本监控只维护一处。
**优先级**：P0

**业务规则**：
1. 新上线的课表照片识别（经 F5）识别质量不得低于原智谱通道基线：以现有课表识别测试夹具做上线前对比评估，识别行准确率不低于原通道（来源：风险缓解，见 §8）。
2. 原挂在课表导入场景的拍照识别同步切换到统一通道（切换后智谱调用归 0）。
3. 视觉通道不可用时的降级口径保持现状：识别类能力明确失败，不影响纯文字查询三条链路。

**异常处理**：

| 异常场景 | 处理方式 | 用户提示 |
|---------|---------|---------|
| 统一通道 API Key 未配置 | 附图入口隐藏（能力级优雅降级，与现知识库降级同模式） | 管理端配置页提示未启用 |
| 模型返回非预期结构 | 按识别失败处理，不落脏数据 | 「没有识别出可靠内容，请换一张更清晰的图」 |

### 3.3 F3 图片意图自动路由（P0）

**功能描述**：根据图片内容+用户配文，自动决定走哪条处理链路，用户不做分类选择。
**用户故事**：作为学生，我希望贴上图就能问，不必先告诉系统"这是课表还是指导书"。
**优先级**：P0

**业务规则**：
1. 路由目标四类：① 课程表类 → F5 查询+草稿；② 文档页类（指导书/教材/制度页）→ F4a 顾问作答；③ 通知/截图/黑板类 → F4b 文字提取+建议追问；④ 无法归类或低置信 → F8 兜底。
2. 路由优先级：用户配文意图 > 图片内容推断。配文明确要查数据（"哪天没课"）即使图片是指导书也按查询处理；配文明确要问知识则按顾问作答。
3. 路由结果必须在「图片理解摘要」中向用户明示（"我把它当作课表来解析"），点错可一键改道（切换路由目标重新执行）。
4. 涉及结构化数据的查询回答，与纯文字查询执行同一套数据权限注入与只读限制（强制 LIMIT、只读）。

**异常处理**：

| 异常场景 | 处理方式 | 用户提示 |
|---------|---------|---------|
| 图片同时含多种内容（课表+通知） | 按配文意图取其一，摘要中说明"图中还包含…" | 提供改道入口（规则3） |
| 路由服务自身异常 | 按 F8 兜底 | 见 3.8 |

### 3.4 F4 文档拍照查询（P0）

**功能描述**：拍实验指导书页、通知、黑板、截图，系统提取图内文字并作答或转述。
**用户故事**：作为学生，我希望拍一页指导书问"这个实验第3步要做什么"，系统结合知识库给出带出处的回答。
**优先级**：P0（F4a 指导书→顾问作答）；P1（F4b 通知/黑板→提取+建议追问）

**业务规则**：
1. F4a：图内文字作为提问上下文，进入知识库顾问作答链路；回答带出处时区分两类来源——「来自你的图片」与「来自知识库」，知识库无命中时明确说"仅按图片内容回答，未找到制度依据"，不猜测（沿用现有"本校事实禁猜"口径）。
2. F4b：输出结构化转述（标题/时间/地点/事项）+ 3 条以内「建议追问」标签，点击标签直接发起后续查询；不写入任何数据。
3. 图片内出现的个人信息（如签到表上的姓名学号）在转述中原样保留但整条查询记入日志（沿用现有查询历史隐私口径）。
4. 纯图无配文时默认执行 F4b（提取+建议追问），作为最轻承诺出口。

**异常处理**：

| 异常场景 | 处理方式 | 用户提示 |
|---------|---------|---------|
| 图片文字模糊/手写体 | 转 F8 兜底 | 见 3.8 |
| 知识库完全无命中 | 仅按图片内容作答并显式标注 | 「以下回答仅依据你的图片，未检索到知识库依据」 |
| 图片为英文/非课件内容 | 正常提取转述，不拒答 | 摘要中注明识别到的语种/类型 |

### 3.5 F5 课表拍照换数据（P0）

**功能描述**：拍纸质课表/考试安排表，系统解析为结构化课程行，既能据此回答查询，也能产出可写回的导入草稿。
**用户故事**：作为教师，我希望拍一张打印的考试安排表问"我这周哪天没课"，确认后还能一键把这些条目加进系统课表。
**优先级**：P0

**业务规则**：
1. 识别产出结构化课程行草稿（字段与原课表导入草稿一致），结果区展示「草稿确认卡」（见 3.6）。
2. 若用户配文是查询（"哪天没课"）：识别结果仅在会话内参与计算并作答，同时提示"检测到 N 条课程条目，可生成导入草稿"，点击才转草稿确认卡——查询不自动触发写回承诺。
3. 草稿写入完全复用现有课表导入的行级校验（时间槽解析、冲突检测）与归属规则：教师提交的条目强制归属本人；管理员提交时可选择归属教师。任一校验失败的行进不了库，逐行标注原因。
4. 识别出的课程行与系统已有课表条目重复时，草稿卡中标注"疑似已存在（同名同时段）"，由用户决定是否仍写入（导入接口现有冲突口径不变）。
5. 草稿确认写入后的反馈与课表页数据一致（写入成功后可在课表页看到）。

**异常处理**：

| 异常场景 | 处理方式 | 用户提示 |
|---------|---------|---------|
| 课表结构无法解析（非表格照片） | 转 F8 兜底 | 见 3.8 |
| 部分行解析成功部分失败 | 成功行进草稿卡，失败行列出原因 | 「12 条中 10 条可导入，2 条时间无法解析」 |
| 写入时课程时间已过期（历史周） | 允许写入（与现有导入一致），但草稿卡标注灰色提示 | 「该课程时间已过，确认仍写入？」 |

### 3.6 F6 草稿确认与写回（出口形态乙）（P0）

**功能描述**：所有结构化识别结果经用户在结果页显式确认后才写入系统。
**用户故事**：作为管理员，我希望模型识别的任何数据都必须过我目确认才入库，以便为错误识别负责的是人不是模型。
**优先级**：P0

**业务规则**：
1. 未经用户点击「确认写入」，任何识别结果不产生写操作（模型输出永不直接入库）。
2. 草稿生命周期 = 当前查询会话：刷新页面/会话结束后草稿失效，明确提示"草稿已过期，请重新拍照"。不落库暂存（来源：拍板决策，最薄实现）。
3. 确认写入走服务端既有校验，前端校验通过不代表写入成功；服务端校验失败的行逐行回显原因，成功的行正常写入（部分成功口径）。
4. 权限：教师仅可确认写入归属本人的条目；管理员可指定归属教师；ADMIN 角色沿用全局只读边界，不得经此入口写入（403，同现有口径）。
5. 写回操作记入与手工新增课表同等的操作日志。

**异常处理**：

| 异常场景 | 处理方式 | 用户提示 |
|---------|---------|---------|
| 确认瞬间他人已写入同条目 | 服务端冲突检测拦截该行 | 「第 X 行与最新课表冲突，未写入」 |
| 会话中途权限变化（如角色被调整） | 确认时重新鉴权 | 「你已无写入权限」 |

### 3.7 F7 课表拍照导入双入口收编（P1）

**功能描述**：课表页现有的"拍照识别导入"入口与智能查询附图通道收敛为同一能力。
**用户故事**：作为教师，我希望无论从哪个入口拍课表，识别行为和结果一致，以免两处版本漂移。
**优先级**：P1

**业务规则**：
1. 课表页拍照入口保留位置不变，但底层统一调用 F2/F5 同一识别与草稿能力；识别模型、校验规则、错误文案单点维护。
2. 两入口写入的归属与权限规则完全一致（3.5 规则3、3.6 规则4）。
3. 收编为内部改造，对课表页用户的可见变化仅限识别质量与错误提示文案统一。

**异常处理**：

| 异常场景 | 处理方式 | 用户提示 |
|---------|---------|---------|
| 统一通道异常导致课表页原入口回归失败 | 保留回退开关：课表页入口可临时切回原链路（一个发布周期内） | 管理端可见开关状态 |

### 3.8 F8 低置信兜底与合规（P0）

**功能描述**：看不清就不答，图片数据全链路合规。
**用户故事**：作为学生，我希望系统宁可说"没看清"也不要拿猜的答案糊弄我。
**优先级**：P0

**业务规则**：
1. 识别置信不足（无法产出可靠摘要/结构）时，明确回复「没看清」+ 具体建议（补光/拍正/配文字），并引导改用文字提问；不得输出猜测性内容（沿用"本校事实禁猜"口径）。
2. 图片本体不持久化：仅在请求内存中转码传给模型通道，服务端不落盘、不缓存原图；查询历史仅记录文字摘要与结果，不记录图片。
3. 图片内容不得绕过任何现有安全边界：不改变只读 SQL 约束、不越权取数、写回仅经 F6 路径。
4. 附图的查询同样计入限流与查询历史时间线（与文字查询同权记账）。
5. 「云识图与校内数据不外传口径」的文档冲突由本 PRD 显式处置：口径改写为"课表/文档类照片经统一模型通道理解，图片不落盘；涉密材料不得拍照上传"，需在文档中标注（依赖：见 §8 风险 R3）。

**异常处理**：

| 异常场景 | 处理方式 | 用户提示 |
|---------|---------|---------|
| 模型返回成功但摘要为空 | 按低置信兜底处理 | 「没有看清图片内容，请重试或改用文字提问」 |
| 触发限流 | 同现有终端限流行为 | 沿用现有「操作过于频繁」提示 |

## 4. 非功能需求

| 类别 | 要求 | 验收标准 |
|------|------|---------|
| 性能 | 附图查询端到端响应 | 单图（≤10MB）P95 ≤ 25s（含识别+回答），纯文字链路不受影响 |
| 性能 | 纯文字查询延迟零回退 | 与改造前基线差异 ≤ 10% |
| 安全 | 上传校验 | 魔数+扩展名双重校验绕过用例 0 通过；图片不落盘（磁盘抽查无新图文件） |
| 安全 | 权限 | ADMIN 写回 403；教师跨归属写回 403；越权取数用例全拦截 |
| 可靠性 | 视觉通道故障隔离 | 识图服务挂掉时三条纯文字链路可用性不变 |
| 兼容性 | 浏览器 | Chrome/Edge 最新两个大版本；移动端浏览器可提交但不承诺优化（与终端现状一致） |

## 5. 数据需求（埋点）

| 事件名 | 触发条件 | 关键属性 | 用途 |
|--------|---------|---------|------|
| `nlq_image_submit` | 含图查询提交 | 图片类型（推断）、有无配文、角色 | 渗透率（目标1） |
| `nlq_route_result` | 意图路由完成 | 路由目标、是否人工改道、置信档位 | 路由质量监控 |
| `nlq_draft_generated` | 草稿卡展示 | 条目数、解析失败行数 | F5 转化漏斗 |
| `nlq_draft_confirm_result` | 点击确认写入返回 | 成功行数、失败行数、失败原因码 | 写回成功率（目标2） |
| `nlq_vision_low_confidence` | F8 兜底触发 | 触发环节（识别/路由/提取） | 兜底正确率抽检 |
| `nlq_vision_error` | 识图链路异常 | 异常类型、耗时 | 可用性与降级监控 |

## 6. 验收标准

| 编号 | 场景 | Given | When | Then |
|------|------|-------|------|------|
| AC-01 | 附图提交 | 教师在 `/nlq` 终端 | 粘贴一张 3MB jpg 并配文"帮我看这周哪天没课"，Ctrl+Enter | 提交成功，结果区先出「图片理解摘要」再出回答；查询历史时间线记录该次含图查询 |
| AC-02 | 格式拦截 | 输入区已添加 pdf 文件 | 尝试提交 | 提交前拦截，提示仅支持 jpg/png/webp；不发起请求 |
| AC-03 | 伪装文件拦截 | 一张 jpg 内容改名 .png 合法 | 提交 | 魔数校验通过；改扩展名的 exe 文件被拒 |
| AC-04 | 课表路由+F5 查询 | 上传清晰纸质课表照片，配文"周一有什么课" | 系统处理 | 路由到课表链路，摘要明示"当作课表解析"，回答基于识别结果且遵守角色数据权限 |
| AC-05 | 查询不自动写回 | 同 AC-04 | 回答完成后 | 页面出现「可生成导入草稿」提示，但无任何写操作发生 |
| AC-06 | 草稿确认写回 | 教师生成课表草稿卡（10 行，8 行合法） | 点击确认写入 | 8 行入库成功、2 行逐行回显失败原因；课表页可见新条目；操作日志有记录 |
| AC-07 | 教师归属强制 | 教师尝试将草稿卡中某行归属改为他人 | 确认写入 | 该行按归属本人写入或拒绝（与现有课表导入口径一致），不发生越权写入 |
| AC-08 | ADMIN 只读 | ADMIN 角色 | 在草稿卡点击确认写入 | 403，提示无写入权限 |
| AC-09 | 指导书问答带出处 | 学生上传指导书页照片问"第三步干什么" | 知识库有对应资料 | 回答标注「来自知识库：xxx 第 N 节」+「来自你的图片」；知识库无命中时显式声明仅依据图片 |
| AC-10 | 通知提取 | 上传黑板通知照片、无配文 | 提交 | 走 F4b：输出标题/时间/地点/事项转述 + ≤3 条建议追问标签，标签可点击发起查询 |
| AC-11 | 低置信兜底 | 上传一张严重模糊的照片 | 提交 | 明确「没看清」+拍摄建议+文字提问引导，无猜测性回答 |
| AC-12 | 改道 | 系统把课表误路由为文档页 | 用户点击「改道」选择课表 | 重新执行并覆盖展示结果，计入 `nlq_route_result` 人工改道 |
| AC-13 | 图片不落盘 | 完成任一附图查询 | 服务器磁盘检查 | 无任何图片文件写入 uploads 目录；重启服务后无残留 |
| AC-14 | 通道收敛 | 部署后运行一周 | 查智谱通道调用日志 | 调用次数为 0；课表页拍照入口功能正常（F7 收编后） |
| AC-15 | 文字链路零回退 | 视觉通道服务被停用 | 提交 5 条纯文字查询 | 三条链路均正常，延迟与基线差异 ≤10% |
