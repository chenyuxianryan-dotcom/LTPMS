> 版本：V1.1（评审修订）｜ 生成日期：2026-09-09  
> 依据：《LTPMS_智能化升级路线图.md》（工程层 V1/V2/V3）+《LTPMS_特色功能创意池.md》（创意层四批次）  
> 修订：补齐 Java 代理缺口、核验 `aggregate_only` 依赖、标注 MCP 权限风险、消除就绪度双实现、统一聚合/文本生成/草稿确认，防臃肿

## 0. 使用说明

- **编号规则**：`T{阶段}.{任务}.{ticket}`，如 `T1.3.2` = 阶段 1 → 任务 3 → 第 2 个工单。
- **每个 ticket 五要素**：目标 / 涉及文件 / 关键操作 / 验收标准 / 风险回滚。
- **依赖**：标注了前置 ticket 的，必须按序完成；未标注的可并行。
- **验收门**：每个阶段末尾设「阶段验收门」，全绿才进下一阶段。
- **改动纪律**：所有写库类能力走「草稿 → 人工确认 → 落库」，Agent 永不直接写库；权限注入链路（`permission.py` / `aggregate_only`）只复用、不重造。

### 执行顺序总览

```
阶段0 前置准备 ──▶ 阶段1 Agent基座+阿实人格 ──▶ 阶段2 视觉导入+数据智能+流程自动化 ──▶ 阶段3 MCP+视觉叙事 ──▶ 贯穿性收尾
   (基线/测试/环境)     (V1 + 创意池第一批)          (V2 + 创意池第二/三批)              (V3 + 创意池第四批)
```

## 阶段 0：前置准备（基线 / 测试 / 环境）

> 目标：让每一次升级都可回滚、可快速验证。**本阶段不写任何业务代码**。

### 任务 T0.1　升级基线与可回滚机制

#### T0.1.1　提交并归档未提交文档

- **目标**：确保基线干净，避免升级代码与文档混在一起。
- **涉及**：`LTPMS_智能化升级路线图.md`、`LTPMS_特色功能创意池.md`、`LTPMS_智能化升级任务清单.md`
- **关键操作**：`git status` 确认工作区 → `git add` 三份文档 → 独立 commit（不含任何代码改动）。
- **验收**：`git status` 干净；文档已入仓库。
- **风险/回滚**：若仓库含明文密钥（`start-all.bat` 内 JWT_SECRET/DB_PASSWORD），仅本地提交不推远端即可。

#### T0.1.2　建立升级分支与基线标签

- **目标**：任何阶段出错可一键回退。
- **涉及**：git 分支
- **关键操作**：`git checkout -b upgrade/agent-v1` → `git tag -a baseline-20260909`。
- **验收**：`git log --oneline` 可见 tag；切回 master 可还原基线。
- **风险/回滚**：`git checkout -f baseline-20260909` 即完整回退。

### 任务 T0.2　测试地基

#### T0.2.1　固化前端冒烟脚本（playwright）

- **目标**：把已跑通的验证流程沉淀为可重复执行的回归脚本，升级后一键回归。
- **涉及**：`scripts/`（新建冒烟用例）、playwright-cli 流程
- **关键操作**：把「登录 → dashboard → 悬浮球展开 → NLQ 查询」链路固化为脚本。
- **验收**：脚本可独立跑通，输出通过/失败清单。
- **风险/回滚**：落地页 hero 左右双 DOM，定位需按 `.landing-page__half--left/--right` 分区，避免「intercepts pointer events」误报。

#### T0.2.2　nlq-service 单元测试骨架（pytest）

- **目标**：为 `permission.py` / `sql_validator.py` / `prompt_builder.py` 补最小单测，升级前先锁行为。
- **涉及**：`nlq-service/tests/`（新建）
- **关键操作**：对权限注入规则（实验/课程/排课 → teacher_id；实验室/学期/字典不注入）与 SQL 危险语句拦截写用例。
- **验收**：`pytest` 全绿。
- **风险/回滚**：注入失败/找不到 teacher 关联必须「拒绝执行」——用测试锁死此行为。

#### T0.2.3　后端接口冒烟脚本

- **目标**：锁死登录/报表/课表导入等核心接口的基线行为。
- **涉及**：`scripts/`（curl 或脚本）、后端 controller 层
- **关键操作**：登录拿 token → 报表汇总（`aggregate_only`）→ 课表导入预览。
- **验收**：脚本输出各接口 code=200 + 预期字段。
- **风险/回滚**：后端 8080 会随会话回收反复掉线，脚本前置需做端口探测。

### 任务 T0.3　环境与密钥

#### T0.3.1　补齐密钥配置

- **目标**：升级前把 DeepSeek / 智谱 key 配好，避免运行时才报缺 key。
- **涉及**：`nlq-service/.env`
- **关键操作**：填真实 `DEEPSEEK_API_KEY`；预置 `ZHIPU_API_KEY=`（空值占位，阶段 2 再填）。
- **验收**：`/health` 带 `X-Internal-Token` 返回 200；查询接口能真实调用 DeepSeek。
- **风险/回滚**：`.env` 不入库；缺 key 时 NLQ 报「AI 服务暂时不可用」属预期降级。

#### T0.3.2　服务自启根治（运维）

- **目标**：消除「会话回收 → 服务掉线」反复发生的根因，升级期间不被环境打断。
- **涉及**：`scripts/ltpms-autostart.bat`、Windows 计划任务
- **关键操作**：注册计划任务（`schtasks` 需用户手动执行，见此前说明）。
- **验收**：重启后四端口（3307/8080/8000/8001）自动就绪。
- **风险/回滚**：仅运维项，不涉及代码。

## 阶段 1：Agent 基座 + 阿实人格（V1 + 创意池第一批）

> 目标：把「单问单答」的 NLQ 升级为「能办事、有名字」的对话式 Agent。**本阶段后端改动集中在 nlq-service，Java 后端最小改动。**

### 任务 T1.0　Java 后端代理升级（多轮会话透传）

#### T1.0.1　agent 多轮接口代理

- **目标**：前端始终经 Java 后端（JWT 鉴权）访问 agent-service，**不直连 8001**，避免绕过鉴权。
- **涉及**：`backend` 新增/升级 `/api/v1/nlq/agent`（多轮会话 + 工具过程透传）
- **关键操作**：Java 持内部令牌转发 8001；多轮 session 由 agent-service 维护，Java 仅无状态透传；工具调用过程以流式或轮询回传。
- **验收**：前端调用走 JWT 鉴权；直连 8001 被内部令牌拦截。
- **风险/回滚**：**勿让前端持有 NLQ_INTERNAL_TOKEN**；会话状态不落 Java 侧，保持无状态代理。

### 任务 T1.1　DeepSeek function calling 升级

#### T1.1.1　工具 schema 传递与解析

- **目标**：让 DeepSeek 支持函数调用（传工具定义、解析 tool_calls）。
- **涉及**：`nlq-service/services/deepseek_client.py`
- **关键操作**：请求体增加 `tools`/`tool_choice`；解析返回的 `tool_calls`。
- **验收**：单测验证「传入一个工具 → 模型返回 tool_call 而非直接答」。
- **风险/回滚**：DeepSeek-chat 无视觉能力（阶段 2 另起 GLM-4V），勿在本次混入图片参数。

#### T1.1.2　Agent 多步循环

- **目标**：实现「计划 → 调工具 → 观察 → 回答」循环。
- **涉及**：`nlq-service/agent/`（新建 loop.py 或等价）
- **关键操作**：循环执行 tool_calls，把工具结果回填进 messages 续轮；上限 N 轮。
- **验收**：教师问「哪门课没建实验项目」可连续调用 2+ 工具给结论。
- **风险/回滚**：循环必须带轮数上限，防失控。

#### T1.1.3　轮数 / 超时 / 频次熔断

- **目标**：保护性约束，防 Agent 失控或打爆 LLM。
- **涉及**：`nlq-service/agent/`、`services/row_limiter.py` 复用
- **关键操作**：max_steps、单工具超时、单位时间调用频次上限、结果行数限制。
- **验收**：构造死循环场景，验证到上限即终止并降级提示。
- **风险/回滚**：沿用已有 `row_limiter`，不另起炉灶。

### 任务 T1.2　工具注册表

#### T1.2.1　统一工具接口与注册

- **目标**：工具统一为「名称 / 描述 / 参数 JSON Schema / 执行器」四元组。
- **涉及**：`nlq-service/services/tool_registry.py`（新建）
- **关键操作**：定义 `Tool` 基类 + `@register_tool` 装饰器。
- **验收**：新增工具零侵入注册，注册表能枚举全部工具。
- **风险/回滚**：参数 schema 必须严格，否则模型传参错乱。

#### T1.2.2　工具发现注入提示词

- **目标**：让 Agent 知道「自己有哪些工具可用」。
- **涉及**：`services/prompt_builder.py`（扩展）
- **关键操作**：把注册表工具名+描述注入系统提示。
- **验收**：Agent 能按描述正确选择工具。
- **风险/回滚**：描述需克制（≤5 词要点），过长会稀释指令遵循度。

### 任务 T1.3　三层工具落地

#### T1.3.1　query_data 只读查询工具

- **目标**：Agent 的通用只读查询能力。
- **涉及**：`services/tools/query_data.py`（新建），复用现有 NL2SQL 全链路（`permission.py` + `sql_validator.py`）
- **关键操作**：工具执行器 = 现有 NL2SQL 流程，天然带权限注入与 SQL 安全校验。
- **验收**：教师查全校数据被强制注入 teacher_id；危险 SQL 被拦截。
- **风险/回滚**：**不绕过 `sql_validator` / `permission`**，这是安全红线。

#### T1.3.2　report_stats 报表统计工具

- **目标**：Agent 回答报表类问题（汇总行、人时数）。
- **涉及**：`services/tools/report_stats.py`（新建），复用后端报表接口
- **关键操作**：调用报表接口，透传权限范围；结果结构化回传。
- **验收**：教师问「全校多少课时」得全校汇总（零明细）；问本人只见本人。
- **风险/回滚**：复用已定的 `aggregate_only` 分层可见；**开工前先核验报表接口是否已实现 `aggregate_only`，未实现则本 ticket 前置补上**（勿假设已存在）。

#### T1.3.3　导入草稿类工具接口预留

- **目标**：为阶段 2 视觉导入预留「生成草稿」通道。
- **涉及**：`services/tools/` 接口约定
- **关键操作**：只定义「返回草稿 + 落库闸门」的接口，不实现写库。
- **验收**：接口可被后续工具实现；写库必经人工确认。
- **风险/回滚**：架构上不存在直接写库工具。

### 任务 T1.4　技能框架

#### T1.4.1　YAML 技能包加载器

- **目标**：声明式技能（名称/描述/参数/prompt 模板/允许工具组合）。
- **涉及**：`nlq-service/skills/`（新建）+ 加载器
- **关键操作**：解析 YAML → 生成技能对象。
- **验收**：技能包随代码内置、可版本管理。
- **风险/回滚**：YAML 语法错误应启动时报错，不静默。

#### T1.4.2　技能发现注入系统提示

- **目标**：让 Agent 按需组合调用技能。
- **涉及**：`prompt_builder.py`
- **关键操作**：技能名+描述注入提示，与工具并列。
- **验收**：Agent 能命中并调用对应技能。
- **风险/回滚**：技能与工具避免职责重叠导致误选。

#### T1.4.3　首发技能包

- **目标**：落地两个首发技能——学期实验项目统计、课程就绪度体检。
- **涉及**：`skills/experiment_stat.yaml`、`skills/readiness_check.yaml`
- **关键操作**：编写 YAML（prompt 模板 + 允许工具组合）。就绪度体检技能**基于 `query_data` 组合实现，是终态逻辑**。
- **验收**：触发技能后正确产出结构化结果。
- **风险/回滚**：就绪度体检只保留「技能」这一套逻辑，阶段 2 的 T2.3 仅做前端可视化 + 复用 Dashboard V3 数据，**不再另造一套聚合逻辑**，避免双实现（见 T2.3）。

### 任务 T1.5　阿实人格（创意池第一批）

#### T1.5.1　人格系统提示

- **目标**：给 Agent 注入「阿实」人设（实验助教，轻快不端）。
- **涉及**：`prompt_builder.py`（系统提示层）
- **关键操作**：名字/身份/语气写入系统提示；语气「说人话不甩术语」。
- **验收**：对话自称阿实、语气统一。
- **风险/回滚**：人设不能影响工具调用正确性，需回归 T1.3 用例。

#### T1.5.2　长期记忆存储

- **目标**：记住教师偏好 / 常用查询 / 上次上下文。
- **涉及**：**agent-service（nlq-service）侧 SQLite/文件存储**，不新增 Java 表；按 `teacher_id` 隔离
- **关键操作**：存非敏感偏好与上下文摘要；key=teacher_id，从 JWT 声明传入。
- **验收**：跨会话可召回；教师间记忆互不可见。
- **风险/回滚**：**记忆放 agent-service，保持阶段 1 Java 后端最小改动**；不存敏感信息、不存明文 token。

#### T1.5.3　上下文延续

- **目标**：登录后阿实主动带出上次未完成的查询。
- **涉及**：前端（读取记忆接口）+ 后端记忆接口
- **关键操作**：登录后拉取最近上下文，渲染「你上次在调 CS101 的实验项目」。
- **验收**：新会话可见上轮上下文入口。
- **风险/回滚**：上下文为空时优雅降级（不显示），不报错。

### 任务 T1.6　前端对话面板升级（阿实对话面板）

#### T1.6.1　多轮对话 + 上下文

- **目标**：悬浮球迷你面板 → 完整对话式面板，多轮上下文。
- **涉及**：`frontend/src/components/NlqWidget.vue`（改造）、`BasicLayout.vue` 挂载不变
- **关键操作**：接入 agent 接口（多轮 session），保留收起不销毁。
- **验收**：连续提问能延续上下文；收起再展开不丢会话。
- **风险/回滚**：接口超时（60s）与错误文案沿用现有 NLQ 错误码链路。

#### T1.6.2　工具调用过程展示

- **目标**：展示「正在查询课程表…」的过程，非干等。
- **涉及**：`NlqWidget.vue`
- **关键操作**：SSE 或轮询渲染工具调用步骤。
- **验收**：调用工具时前端有过程反馈，结束后显示结果。
- **风险/回滚**：过程展示失败不阻断结果返回。

#### T1.6.3　复古终端视觉 + 阿实包装

- **目标**：面板做成老式终端风，与首页「智能查询」分页视觉统一。
- **涉及**：`NlqWidget.vue` + 样式
- **关键操作**：磷光绿、扫描线、闪烁光标、阿实头像/名字。
- **验收**：视觉与首页统一，一眼认出「阿实」。
- **风险/回滚**：SVG 装饰用 viewBox 0-100 + `preserveAspectRatio="none"`，polyline points 只接受纯数字（踩坑记录）。

#### T1.6.4　结果表格渲染

- **目标**：查询结果以紧凑表格呈现，超长可滚动/跳转。
- **涉及**：`NlqWidget.vue`
- **关键操作**：复用现有「前 5 行 + 查看完整结果跳 /nlq」模式。
- **验收**：结果表格正确渲染，跳转正常。
- **风险/回滚**：空结果/超长/多列需有兜底。

### 任务 T1.7　安全

#### T1.7.1　权限注入角色验证

- **目标**：确认升级后权限注入对教师/管理员均正确生效。
- **涉及**：`permission.py` 回归
- **关键操作**：教师角色查全局 → 被注入 teacher_id；管理员 → 全校。
- **验收**：T0.2.2 单测覆盖并通过。
- **风险/回滚**：注入失败拒绝执行，不放行零权限查询。

#### T1.7.2　熔断兜底

- **目标**：LLM 超时/限流/循环失控时优雅降级。
- **涉及**：agent 循环层
- **关键操作**：超时、429、异常统一映射到现有错误文案（NLQ_UNSAFE / NLQ_MODEL_TIMEOUT 等）。
- **验收**：模拟超时/429，前端提示「AI 服务暂时不可用」而非 500。
- **风险/回滚**：复用现有错误码文案，不新增新码。

### 任务 T1.8　阶段 1 验收门

- **验收**：教师问「我这学期哪门课还没建实验项目？帮我统计一下学时」→ 阿实连续调用 2+ 工具给出正确结论；管理员问全校数据得到权限正确的汇总。
- **通过条件**：pytest 全绿 + playwright 冒烟通过 + 控制台 0 错误 + `vue-tsc`/`mvn` 构建通过。

## 阶段 2：视觉导入 + 数据智能 + 流程自动化（V2 + 创意池第二/三批）

> 目标：拍照代替 Excel，并让阿实「主动说话、主动办事」。**本阶段开始改 Java 后端（新增聚合接口）。**  
> 拆分：**2A（视觉导入）** 与 **2B（数据智能 + 流程自动化）** 两个子阶段，各自独立验收门，避免一次性改动过大。

### 任务 T2.0　数据智能聚合服务统一设计（防臃肿前置）

#### T2.0.1　聚合服务统一入口

- **目标**：把本阶段多类数据智能（就绪度/热力图/异常/冲突）归入**一个聚合服务 + 统一查询层**，而非各建一个 ad-hoc controller。
- **涉及**：`backend` 新建聚合 service（复用现有 mapper/查询）

## 附录：关键红线（贯穿所有 ticket）

1. **Agent 永不直接写库**——所有写意图终止于「草稿 → 人工确认 → 落库」。
2. **权限注入只复用不重造**——`permission.py` / `aggregate_only` 是唯一权限事实源，注入失败即拒绝执行。
3. **SQL 安全校验不绕过**——`sql_validator` 只读、防危险语句，任何工具都走它。
4. **已知踩坑速查**：SVG polyline 只接受纯数字；落地页双 DOM 定位按 `--left/--right`；401 统一在 `request.ts` + `store/user.ts` 的 JWT exp 校验；MySQL8 连库需 `cryptography`；后端 8080 易被会话回收（用计划任务根治）。
5. **防臃肿复用约定**（避免代码冗余）：
   - **就绪度判定只有一处真源**——Dashboard V3 语义 + T1.4.3 技能（基于 query_data），T2.3 只做可视化，不复制逻辑。
   - **后端聚合走统一服务**——热力图/异常/冲突归入 T2.0 聚合服务，不各建 controller 重写 SQL。
   - **LLM 文本生成共享一个工具**——材料清单（T2.7）/数字档案（T3.2）/叙事报告与教学总结（T3.3）共用一个 `generate_text` 工具 + 各自的 prompt 模板（技能化），不重复写 4 套 LLM 调用代码。
   - **草稿确认流复用**——课表导入（T2.2）与学期迁移（T2.8）共用一个「草稿预览 + 确认落库」组件，不各写一套。
