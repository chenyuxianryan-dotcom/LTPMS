# 01 项目立项与审批文档

> **适用系统**：LTPMS（实验教学项目管理系统）  
> **文档版本**：V2.0  |  **编制日期**：2026-09-21  
> **审批链路**：需求提出方 → 技术负责人 → 教务处 → 分管校领导

## 1. 项目概述

### 1.1 项目名称

实验教学项目管理系统（Laboratory Teaching Project Management System，简称 LTPMS）

### 1.2 项目背景

| 维度 | 现状痛点 | 预期改进 |
|------|----------|----------|
| 实验室排课 | 课表以 Excel + 照片传递，排课冲突依赖人工排查 | 结构化排课 + 时间槽冲突检测 |
| 实验项目管理 | 课程实验与独立课题分散在多个文档中，成员/任务/数据无可追溯性 | 统一「课程容器→实验目录→工作区」三级结构 |
| 学生名单 | 每学期教师手动维护选课名单，容易遗漏或重复 | Excel 导入 + 学号自动建档 + 课程选课表联动 |
| 统计报表 | 实验人时数、利用率等指标需要人工汇总多个 Excel | 一键生成报表，支持导出 Excel/PDF |
| 数据查询 | 非技术人员无法自主查询教学数据 | AI 自然语言查询（NL2SQL）+ Agent 智能问答 |

### 1.3 项目目标

| 目标类型 | 目标描述 | 量化指标 |
|----------|----------|----------|
| 功能目标 | 覆盖实验室→学期→排课→课程→实验项目→报表全链路 | 8 大模块全部上线 |
| 效率目标 | 教师学期初排课耗时下降 | 从平均 3 天降至 0.5 天 |
| 数据目标 | 实验室利用率可按周/月/学期自动统计 | 报表导出耗时 < 5 秒 |
| 智能目标 | 支持自然语言查询教学数据 | NL2SQL 首轮成功率 ≥ 70% |
| 用户目标 | 三类角色（管理员/教师/学生）均有专属工作台 | 角色覆盖 100% |

### 1.4 项目范围

#### 包含范围（In Scope）

| 模块编号 | 模块名称 | 主要功能 | 关联数据库表 |
|----------|----------|----------|-------------|
| M1 | 系统数据管理 | 实验室 CRUD/导入、学期管理、排课管理、教师账号、字典管理 | `laboratory` `semester` `schedule` `schedule_time` `user` `dictionary` `holiday` |
| M2 | 实验项目管理 | 课程容器自动生成、实验目录 CRUD/复制、成员管理、任务管理、数据集、进度追踪 | `lab_project` `lab_project_member` `lab_project_task` `lab_task_submission` `lab_dataset` `lab_dataset_version` `lab_comment` |
| M3 | 学生名单管理 | 课程选课名单导入、学号自动建档、课程名单联动 | `student` `course_student` `user` |
| M4 | 报表中心 | 实验人头数报表、人时数报表、导出 Excel/PDF | 聚合查询多表 |
| M5 | 数据智能 | 课程就绪检查、利用率热力图、异常预警、排课冲突检测 | 聚合查询多表 |
| M6 | AI 助手「阿实」 | NL2SQL 单轮/多轮、人员档案八维卡片、可视化导入（课表拍照识别）、实验台数字档案 | `query_history` + NL2SQL 微服务 |
| M7 | MCP 只读服务 | 对外暴露系统数据供 AI 客户端消费 | 全站只读 |
| M8 | 系统公共 | 登录、改密、头像、通知中心、操作审计（AOP） | `notification` `operation_log` |

#### 排除范围（Out of Scope）

| 排除项 | 排除理由 | 后续计划 |
|--------|----------|----------|
| 移动端 App | 一期聚焦 Web 端，移动端需求尚不明确 | Phase 2 评估 |
| 跨校区实验室调度 | 当前仅覆盖单一校区 | 视需求扩展 |
| 学生成绩评定 | 与教务系统成绩模块职责重叠 | 对接教务系统 |
| 设备采购审批流 | 职能属于资产管理系统 | 外部系统集成 |
| 财务报销审批流 | 职能属于财务系统 | 外部系统集成 |

## 2. 技术方案概述

### 2.1 技术架构

```
┌─────────────────────────────────────────────────────────────┐
│                        用户层                                │
│  管理员 / 教师 / 学生 → 浏览器 → Vue3 + Element Plus SPA     │
└──────────────────────────┬──────────────────────────────────┘
                           │ HTTP / JWT
┌──────────────────────────▼──────────────────────────────────┐
│                      网关层                                  │
│  Spring Boot 3.3 + 拦截器 (角色鉴权 + 操作审计 AOP)          │
└──────────────────────────┬──────────────────────────────────┘
                           │
┌──────────────────────────▼──────────────────────────────────┐
│                     业务服务层                                │
│  M1~M8 八大模块 Service 层                                   │
│  MyBatis-Plus ORM → MySQL 8.4                               │
└──────────────────────────┬──────────────────────────────────┘
                           │
┌──────────────────────────▼──────────────────────────────────┐
│                    AI 服务层                                  │
│  Python FastAPI NL2SQL 微服务 (DeepSeek)                     │
│  Agent 工具调用 / MCP 只读服务                                │
└─────────────────────────────────────────────────────────────┘
```

### 2.2 数据库设计原则

| 原则 | 说明 |
|------|------|
| 逻辑外键 | 应用层保证完整性，不使用数据库物理外键 |
| 软删除 | `lab_project_task.deleted`、`user.status` 等字段控制 |
| 审计追踪 | `operation_log` 表记录全站写操作（AOP 自动采集） |
| 唯一键约束 | `student_no`、`lab_code`、`project_code`、`(course_code, semester_id)` 等业务唯一键 |
| 字符集统一 | 全表 `utf8mb4_unicode_ci` |

### 2.3 部署架构

| 组件 | 部署方式 | 端口 |
|------|----------|------|
| 前端 | Nginx 静态部署 / Docker | 80/443 |
| 后端 | Spring Boot JAR / Docker | 8080 |
| NL2SQL | Python FastAPI / Docker | 8000 |
| 数据库 | MySQL 8.4 / Docker | 3306 |
| 编排 | docker-compose.yml | — |

## 4. 风险评估

| 编号 | 风险描述 | 概率 | 影响 | 应对策略 |
|------|----------|------|------|----------|
| R1 | 学生首次登录强制改密流程与现有登录页冲突 | 中 | 高 | 复用 `LoginPage.vue` 的 `isDefaultPwd` 拦截，前端守卫 fallback |
| R2 | NL2SQL 查询准确率不达标 | 中 | 中 | 设置查询历史表 `query_history`，失败查询人工审核 + prompt 优化 |
| R3 | 学号与教师工号冲突 | 低 | 高 | `user.uk_username` 唯一约束 + 导入时检测冲突并拒绝（r2-C2 规则） |
| R4 | 大量并发导入导致数据库锁 | 低 | 中 | 事务粒度控制 + 批量导入逐行 upsert |
| R5 | 跨学期数据迁移复杂 | 中 | 中 | 学期状态机（UPCOMING→ACTIVE→ENDED）+ 历史数据只读 |

```

    ↓ 提交立项申请
```
