## 1. 进度管理体系概述

### 1.1 进度追踪维度

LTPMS 从三个维度追踪实验教学进度：

```
进度追踪体系
├── 项目维度（lab_project）
│   ├── 完成度 = 已验收任务数 / 总任务数 × 100%
│   ├── 成员完成率 = 各学生已验收任务数 / 分配任务数
│   └── 逾期率 = 逾期任务数 / 总任务数 × 100%
├── 任务维度（lab_project_task）
│   ├── 5 状态状态机：NOT_STARTED → IN_PROGRESS → SUBMITTED → ACCEPTED/REJECTED
│   └── 截止日期（deadline）+ 逾期标记
└── 课程维度（course + experiment + schedule）
    ├── 课程就绪度 = 已建实验项目数 / 教学大纲要求数
    ├── 实验完成率 = 已完成实验数 / 总实验数
    └── 排课执行率 = 实际授课数 / 计划排课数
```

### 1.2 任务状态机

```
NOT_STARTED（未开始）
    │ 教师指派任务
    ▼
IN_PROGRESS（进行中）
    │ 学生提交成果
    ▼
SUBMITTED（已提交）─── 教师审核 ───┐
    │                              │
    │ 审核通过                      │ 审核驳回
    ▼                              ▼
ACCEPTED（已验收）              REJECTED（已驳回）
                                    │ 学生重新提交
                                    ▼
                               SUBMITTED（已提交）

CLOSED（已关闭）── 教师关闭 / 成员移出时自动关闭
```

### 1.3 热力矩阵

进度 Tab 展示学生×任务热力矩阵：

| 格色 | 状态 | 含义 |
|------|------|------|
| 绿色 | ACCEPTED | 已验收 |
| 黄色 | IN_PROGRESS / SUBMITTED | 进行中 / 待验收 |
| 红色 | 逾期未提交 | 超过 deadline 仍未提交 |
| 灰色 | NOT_STARTED | 未开始 |

行尾 = 该生完成率，列尾 = 该任务通过/总人数

## 3. 进度监控看板

### 3.1 关键指标（KPI）

| KPI | 计算公式 | 目标值 | 预警阈值 |
|-----|----------|--------|----------|
| 项目完成度 | ACCEPTED 任务数 / 总任务数 | ≥ 80% | < 60% |
| 任务逾期率 | 逾期任务数 / 总任务数 | ≤ 10% | > 20% |
| 提交及时率 | 按时提交数 / 应提交数 | ≥ 90% | < 70% |
| 审核响应时间 | 从提交到审核的平均时长 | ≤ 3 天 | > 5 天 |
| 数据集更新频率 | 每项目每周平均版本数 | ≥ 1 | < 0.5 |
| 成员活跃率 | 本周有提交的学生 / 总成员 | ≥ 80% | < 50% |

### 3.2 数据提取路径

| KPI | LTPMS 数据提取方式 |
|-----|-------------------|
| 项目完成度 | 项目详情 → 进度 Tab → 汇总条 |
| 任务逾期率 | 任务列表 → 筛选「已逾期」 |
| 提交及时率 | 任务提交记录 → deadline 对比 |
| 审核响应时间 | `lab_task_submission` 时间戳差值 |
| 数据集更新频率 | `lab_dataset_version` 按周分组 |
| 成员活跃率 | `lab_project_member` × `lab_task_submission` 联查 |

## 5. 结题验收标准

### 5.1 验收检查清单

| 检查项 | 验收标准 | LTPMS 数据佐证 | 通过条件 |
|--------|----------|---------------|----------|
| 任务完成率 | 所有任务达到 ACCEPTED 或 CLOSED | 进度矩阵绿色+灰色 | ≥ 90% |
| 逾期控制 | 逾期任务数不超过总任务 20% | 任务列表逾期筛选 | ≤ 20% |
| 数据完整性 | 每个已验收任务至少有 1 个数据集版本 | `lab_dataset_version` 记录 | 100% |
| 审核合规 | 驳回任务均有审核意见 | `review_comment` 非空 | 100% |
| 成员参与 | 所有成员至少完成 1 个任务 | 成员完成率 > 0 | 100% |
| 操作可追溯 | 关键操作有审计日志 | `operation_log` 记录 | 存在 |

### 5.2 验收结论

| 结论 | 条件 | 后续处理 |
|------|------|----------|
| 通过 | 全部检查项达标 | 项目归档（status=ARCHIVED） |
| 有条件通过 | 主要指标达标，个别任务未完成 | 限期整改，逾期后自动归档 |
| 不通过 | 任务完成率 < 60% 或数据严重缺失 | 需补充完成后重新申请结题 |

## 6. 归档管理

### 6.1 归档内容

| 归档项 | 存储位置 | 保留期限 |
|--------|----------|----------|
| 项目基本信息 | `lab_project` (status=ARCHIVED) | 永久 |
| 成员快照 | `lab_project_member` | 永久 |
| 任务记录 | `lab_project_task` | 永久 |
| 提交历史 | `lab_task_submission` | 永久 |
| 数据集及版本 | `lab_dataset` + `lab_dataset_version` | 永久 |
| 评论记录 | `lab_comment` | 永久 |
| 操作日志 | `operation_log` | 3 年 |

### 6.2 归档后权限

| 角色 | 归档后权限 |
|------|-----------|
| ADMIN | 只读（不可修改） |
| TEACHER | 只读（不可修改，仅本人项目） |
| STUDENT | 只读（仅本人参与的项目） |

### 6.3 数据导出

结题前建议导出以下数据备份：

| 导出项 | 格式 | 导出方式 |
|--------|------|----------|
| 项目进度矩阵 | 截图/PDF | 浏览器打印 |
| 任务清单 | Excel | 报表中心导出 |
| 数据集文件 | ZIP | 批量下载 |
| 操作日志 | Excel | 管理员导出 |
| 审核记录 | Excel | 任务提交记录导出 |
