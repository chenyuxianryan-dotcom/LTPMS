# 02 实验方案与原始记录

> **适用系统**：LTPMS（实验教学项目管理系统）  
> **文档版本**：V2.0  |  **编制日期**：2026-09-21  
> **关联模块**：M2 实验项目管理 + M3 学生名单管理  
> **关联数据库表**：`experiment` `lab_project` `lab_project_task` `lab_task_submission` `lab_dataset` `lab_dataset_version` `course` `student` `course_student`

---

## 1. 实验方案体系概述

### 1.1 三级结构

LTPMS 采用「课程容器 → 实验目录 → 项目工作区」三级结构管理实验教学：

```
课程容器（SYSTEM，自动生成）
├── 实验目录（Tab，教师 CRUD / Excel 导入 / 从上学期复制）
│   ├── 实验项目 A（workspace: 成员 / 任务 / 数据 / 进度四 Tab）
│   │   ├── 成员：学生名单快照（CREATE/MANUAL/COURSE_SNAPSHOT）
│   │   ├── 任务：任务指派 → 提交 → 审核（5 状态状态机）
│   │   ├── 数据：数据集 → 版本链（append-only）
│   │   └── 进度：学生×任务热力矩阵
│   └── 实验项目 B ...
└── 实验目录（下一门课）
```

### 1.2 实验方案生命周期

| 阶段 | 对应操作 | 数据流向 |
|------|----------|----------|
| 方案编制 | 教师创建实验项目、设定任务 | `experiment` + `lab_project` + `lab_project_task` |
| 人员组建 | 从学生库勾选或课程名单一键带入 | `lab_project_member` (source=CREATE/MANUAL/COURSE_SNAPSHOT) |
| 方案执行 | 学生领取任务、提交数据、上传文件 | `lab_task_submission` + `lab_dataset` + `lab_dataset_version` |
| 方案审核 | 教师审核提交、驳回/验收 | `lab_task_submission.review_comment` |
| 方案归档 | 项目归档（只读） | `lab_project.status = ARCHIVED` |

## 2. 实验方案编制规范

### 2.1 实验项目字段定义

| 字段 | 数据类型 | 必填 | 说明 | 示例 |
|------|----------|------|------|------|
| experiment_code | VARCHAR | 自动生成 | 课程+学期+序号，如 CS101-2025A-001 | CS101-2025A-001 |
| experiment_name | VARCHAR(128) | 是 | 实验项目名称 | 数据结构综合实践 |
| category | ENUM | 是 | 实验类别（字典管理） | basic / comprehensive / design / innovation / virtual |
| type | ENUM | 是 | 实验类型 | verification / demonstration / comprehensive / design / research |
| subject | ENUM | 是 | 面向学科 | cs / se / network / ai / security / iot / data_science / electronics |
| requirement | ENUM | 是 | 必修/选修 | required / elective |
| experimenter_type | ENUM | 是 | 实验者类别 | undergraduate / graduate |
| group_size | INT | 是 | 每组人数 | 3 |
| hours | DECIMAL | 是 | 实验学时 | 16.0 |
| sort_order | INT | 否 | 排序号（同课程内有序） | 1 |

### 2.2 实验方案编写模板

```markdown
## 实验方案：[实验名称]

### 一、实验目的
[描述本次实验要达到的教学目标，与课程教学大纲的对应关系]

### 二、实验原理
[相关理论基础、算法原理、技术框架说明]

### 三、实验环境
- 硬件环境：[实验室编号]，设备 [device_count] 台
- 软件环境：[操作系统、开发工具、数据库版本等]

### 四、实验内容与步骤
1. [步骤 1：环境搭建]

3. [步骤 3：测试验证]
4. [步骤 4：结果分析]

### 五、实验数据要求
- 输入数据：[格式、来源、规模]
- 输出数据：[格式、验收标准]
- 数据存储：[上传至 LTPMS 数据集，支持版本管理]

### 六、实验报告要求
1. [报告格式：Word/PDF/Markdown]
2. [必须包含的内容：流程图、代码截图、运行结果、分析总结]
3. [提交方式：通过 LTPMS 任务提交功能上传]

### 七、评分标准
| 维度 | 权重 | 评分标准 |
|------|------|----------|
| 完成度 | 40% | 任务状态达到 ACCEPTED |
| 代码质量 | 20% | 代码规范、注释完整 |
| 报告质量 | 25% | 分析深入、图表清晰 |
| 创新性 | 15% | 超出基本要求的创新点 |
```

## 3. 实验方案批量管理

### 3.1 Excel 批量导入

通过 `POST /experiments/import` 接口批量导入实验方案，模板格式：

| 列名 | 字段映射 | 说明 |
|------|----------|------|
| 实验编号 | experiment_code | 可选，留空自动生成 |
| 实验名称 | experiment_name | 必填 |
| 实验类别 | category | 字典 value（如 basic） |
| 实验类型 | type | 字典 value（如 verification） |
| 面向学科 | subject | 字典 value（如 cs） |
| 必修/选修 | requirement | required / elective |
| 实验者类别 | experimenter_type | undergraduate / graduate |
| 每组人数 | group_size | 正整数 |
| 学时 | hours | 正数 |

导入模板下载：`GET /experiments/import/template`

### 3.2 从上学期复制

`POST /experiments/copy` 接口支持将上一学期的实验方案整批复制到当前学期，自动关联新学期的课程 ID。

## 4. 原始记录管理

### 4.1 任务提交原始记录

LTPMS 中实验原始记录通过「任务提交」机制管理，每条记录包含：

| 字段 | 数据类型 | 说明 |
|------|----------|------|
| task_id | BIGINT | 关联任务 ID |
| submitter_student_id | BIGINT | 提交学生 ID |
| content | TEXT | 提交内容（文字描述、实验过程记录） |
| dataset_version_id | BIGINT | 关联数据集版本（文件类原始数据） |
| reviewed_by | BIGINT | 审核教师 ID |
| review_comment | TEXT | 审核意见 |
| created_at | DATETIME | 提交时间 |

**关键约束**：
- 提交记录为 **append-only**（追加模式，不可修改历史提交）
- 驳回后重新提交产生新行，保留历史记录
- 任务状态流转：`NOT_STARTED → IN_PROGRESS → SUBMITTED → ACCEPTED/REJECTED`

### 4.2 数据集版本链

实验原始数据（代码文件、数据文件、报告文件）通过数据集版本链管理：

```
数据集：lab_dataset
├── 版本 1：lab_dataset_version (version_no=1)
│   ├── stored_path: /uploads/uuid1.py
│   ├── original_filename: main.py
│   ├── file_size: 2048
│   ├── file_type: application/x-python
│   ├── note: "初始版本"
│   └── 评论：lab_comment (target_type=DATASET_VERSION)
├── 版本 2：lab_dataset_version (version_no=2)
│   ├── stored_path: /uploads/uuid2.py
│   ├── note: "修复 bug #3"
│   └── 评论：...
└── ...
```

**版本链规则**：
- 仅追加，不可删除历史版本
- 文件存储使用 UUID 重命名，避免冲突
- 上传时通过 magic-number 校验文件类型
- 最大文件大小：50MB（可配置）

### 4.3 原始记录归档规范

| 归档类型 | 归档内容 | 归档时机 | 存储位置 |
|----------|----------|----------|----------|
| 实验代码 | Python/Java/C++ 源文件 | 每次提交 | `lab_dataset_version.stored_path` |
| 实验数据 | CSV/JSON/SQL 数据文件 | 实验完成后 | `lab_dataset_version.stored_path` |
| 实验报告 | Word/PDF 报告文件 | 每次提交 | `lab_dataset_version.stored_path` |
| 审核记录 | 审核意见、驳回原因 | 每次审核 | `lab_task_submission.review_comment` |
| 操作日志 | 全站写操作记录 | 实时 | `operation_log` |

## 5. 原始记录审查表

### 5.1 审查清单

| 审查项 | 审查标准 | 审查方式 | 记录字段 |
|--------|----------|----------|----------|
| 提交完整性 | 所有必填任务均达到 ACCEPTED 状态 | 进度矩阵检查 | `lab_project_task.status` |
| 数据真实性 | 文件修改时间与提交时间匹配 | `lab_dataset_version.created_at` 对比 | 文件时间戳 |
| 版本一致性 | 最终提交的文件版本号与审核版本一致 | `dataset_version_id` 匹配 | `lab_task_submission.dataset_version_id` |
| 审核合规性 | 驳回需附审核意见 | `review_comment` 非空检查 | `lab_task_submission.review_comment` |
| 操作可追溯 | 关键操作均有审计日志 | `operation_log` 查询 | `operation_log.detail` |

## 6. 实验安全与合规

### 6.1 数据安全措施

| 安全措施 | 实现方式 | 关联模块 |
|----------|----------|----------|
| 文件类型校验 | magic-number 校验，非白名单类型拒绝上传 | `lab_dataset_version` |
| 文件大小限制 | 单文件 50MB 上限 | 上传接口 |
| 存储隔离 | UUID 重命名 + 随机目录，防止路径遍历 | `stored_path` |
| 访问控制 | 项目成员才能访问项目数据，学生不可跨项目 | `lab_project_member` 校验 |
| 操作审计 | 全站写操作记录 IP、用户、操作详情 | `operation_log` |
| 数据脱敏 | 学生学号+姓名仅教师可见，AI 查询不返回个人信息 | NL2SQL 层过滤 |

### 6.2 伦理与隐私

- 学生学号+姓名+班级属个人信息（PIPL 口径下的最小必要收集）
- 提交内容/评语半透明是**后端字段裁剪**而非前端遮罩
- 教师间数据隔离 = 现有 `teacher_id` 行级模式
- 学生不获跨项目可见性
