## Section 1 — Summary

在 LTPMS（实验室教学工作流系统）中新增教师端牵头的「课题项目」模块：老师创建课题项目、从学生库或课程名单拉一批学生进项目、以扁平任务清单派发任务并验收，师生在同一项目空间内共享实验数据（文件级、版本链式），系统以"学生 × 任务"热力矩阵和完成度百分比量化呈现项目进展。主用户是带课题的**实验课教师**，次用户是被拉进课题的**学生**（本模块首次让 LTPMS 出现 STUDENT 角色）。之所以是现在：系统已有课程/学期/报表/权限骨架，但"学生"只存在于 `student_count` 一个数字里——课题制教学与学科竞赛是实验室当前无法用现有模块承载的真实工作流。成功的样子：**一个老师能在 30 分钟内建好项目、导入 20 个学生、派完第一周任务，并在 4 周后凭一张矩阵图说清"谁、在哪件事上、卡了几天"**。

## Section 2 — Background & Problem

**问题（学生视角）**：我进了老师的课题组，任务靠微信群口头派、数据靠网盘文件夹互传、做到哪了没人记得清；期末老师要总结进度，全班陪着回忆。

**问题（教师视角）**：我想给每个学生明确的交付物和截止时间，想随时看到全组进展，想让学生传的数据不再散落——但 LTPMS 现有的「实验项目」是实验课目录（2 学时一次的那种），完全不是课题制的工作单元。

**当前 workaround**：微信群派活 + 网盘传数据 + Excel 记完成名单 + 口头 check。不够好的原因：无验收锚点（学生说做完≠做完）、无版本审计（数据被覆盖说不清）、无量化（"大概做得差不多了"）。

**为什么是现在**：
1. 决策拷问（2026-09-18）已确认系统具备全部承接骨架：用户/JWT/角色注解/Excel 导入管线/通知表/报表页均可复用，新增成本集中在新实体而非基建。
2. Q1 拍板学生成为一等公民账号——这是全系统第一次出现 STUDENT 角色，早做早让 `student` 数据反哺课表（现在只有班级名串）。
3. 课题/竞赛/大创按学期天然滚动，错过开学季窗口，本模块一个学期没有冷启动客户。

**本 PRD 故意不解决**：
- **实验课内的分组实验**（那是现有 `/experiments` 的职责，两者仅命名区分：新模块叫「课题项目」，表前缀 `lab_project*`，旧模块不改名不动——Q7 已定）。
- **学生自助注册与选课**（学生账号只能由教师端产生——Q1 已定；课程挂靠仅到"名单快照"深度，不做实时同步——Q3 已定）。

## Section 3 — Personas & User Segments

**Primary persona（主用户）**

```
姓名：李老师
身份：本校实验室教师，带 2 个大创课题 + 1 个竞赛组，共约 25 名学生
情境：开学初要把假期实验安排转成任务派下去；周中想知道谁卡住了；期末要拿数据写总结
JTBD：当课题需要持续推进时，李老师想把"派活—干活—交活—验收"搬进系统并量化留痕，
      从而不必靠微信群记忆和 Excel 手工记账来掌握全组进展。
当前 workaround：微信群通知 + 网盘传数据 + 个人 Excel 进度表
痛点：没有验收 gate，完成度全是自报；数据版本互相覆盖出过纠纷；跨课题的学生成绩分散无法汇总
```

**Secondary persona（次用户 — B2B 式"买/用分离"：老师=买家，学生=使用者）**

```
姓名：张同学
身份：大二学生，同时在 2 个课题项目里，手机号登录都嫌重，更别说再记一套密码
情境：老师给了他一个"清洗传感器 CSV"的任务，附了原始数据文件
JTBD：当被派任务时，张同学想在一个页面看到"我要交什么、截止啥时候、原始数据在哪"，
      交完能立刻知道老师有没有验收、驳回理由是什么，从而不用反复私聊追问。
当前 workaround：QQ/微信传文件，口头问进度
痛点：怕误删别人的数据；不知道别的组做到哪（想参考但不想被示众打分）
```

**这个产品不为谁做**：不为实验室行政管理员做排期/开放管理（现有模块已覆盖），不为全校学生做统一教务门户——学生身份生命周期完全由教师端掌控。

## Section 4 — Goals & Success Metrics

**产品目标**：让课题制工作流（建项目→派任务→共享数据→验收→量化）第一次在 LTPMS 里完整闭环，且交付成本不随项目数线性增长（Q 系列拷问的贯穿口径）。

**成功度量表**（一期以内部试点验证为目标，不设增长型 KPI）：

| 指标 | 度量什么用户行为 | 目标值 | 时间窗 |
| --- | --- | --- | --- |
| 冷启动完成率 | 老师从建项目到派完首批任务 | ≤30 分钟（计时测试） | 上线前内测 |
| 任务验收流转率 | 已提交任务在 7 天内被老师验收 | ≥80% | 一学期 |
| 学生端周活 | 项目内学生每周至少登录 1 次 | ≥60% | 上线后 30 天 |
| 数据共建渗透 | 项目中由**学生**上传的数据版本占比 | ≥40% | 一学期 |
| 矩阵使用率 | 老师打开详情页后查看 progress 矩阵 | ≥70% | 上线后 30 天 |

**Anti-metrics（反指标，明确不优化）**：
1. **不优化"学生提交量"**——刷任务数会诱导老师把任务拆碎凑 KPI，考核信度反被破坏；量化只认「已验收」锚点（Q4 已定）。
2. **不优化"横向比较刺激"**——学生端不展示他人评分/评语（Q6 半透明），宁可比"活跃度"低一点，也不做排行榜示众。

**关键假设**（错了就做错产品）：**老师和学生真的愿意为课题工作单独登录一个 Web 系统**，而不是继续留在微信群。验证方式 = 第一个真实课题跑 2 周，看学生端周活与提交是否离开微信仍能发生（见 Section 7 风险 R1）。

## Section 5 — Value Proposition

**对主用户（老师）**：

> 李老师终于可以**用一张学生×任务矩阵掌握全组进展、用「验收」一个动作定义完成**，而不必在微信群考古和 Excel 手工对账，因为任务状态机以教师验收为唯一锚点、量化视图与验收同源零口径漂移。

**对学生（使用者）**：

> 张同学终于可以**在一个页面领任务、下数据、交作业、看驳回意见**而不必担心误删同学成果，因为版本链只增不覆盖 + 半透明可见性挡住了示众和扯皮。

**竞争差异化**（对校内替代方案与通用工具）：
- 钉钉/飞书项目、Teambition 类：通用协作工具没有**教师验收 gate 和学生级完成率**这两个校园考核原生概念，也没有和学校 LTPMS 已有的课程/学期/课表数据打通——本模块项目可直接打课程/学期标签（Q2 双模式）。
- 微信+网盘（真实对手）：赢在零成本，输在无留痕无版本；本模块的迁移钩子是"名单 Excel 一拖就进来"（自动建档）+ 学生端只有两个页面，学习成本≈0。

### S1 教师创建课题项目并集结成员 ⭐关键假设 Story

**Persona**：李老师
**Job**：开学建组 → 把学生变成可登录、可被考核的系统内成员
**优先级**：P0　**关键假设标记**：⭐

**功能描述**：老师新建课题项目（名称/说明/可选课程与学期标签），在项目内从学生库勾选成员，或从该课程的已导入名单**一键带入（快照）**；导入学生名单时遇陌生学号**自动建档**（学号=登录名，默认密码，首登强制改密）。

**In Scope**：
- `lab_project` CRUD + 归档态；`project_code` 唯一编号
- 成员快照表 `lab_project_member`（source: CREATE/MANUAL/COURSE_SNAPSHOT）
- 学生批量建档（Excel 导入，复用 `ImportDialog` + POI 管线，含导入回执：成功/失败/新建账号）；**导入校验：学号已被非 STUDENT 用户占用（工号撞学号，`user.uk_username`）→ 拒绝并入失败回执（r2-C2）**
- 课程选课名单 `course_student` 导入与查看（Q3）
- **学生密码重置通道（r2-C3）**：该生任一在管课题的老师可重置为默认密码，写 `operation_log`；避免两老师共享账号时"无人能救"

**Out of Scope**：成员实时跟随课程名单变动（快照语义永久拒绝）；学生自助注册；分组/小组（Q4）。

**验收标准（Given/When/Then）**：
- Given 老师上传一份含 5 个已有学号 + 3 个陌生学号的名单，When 点击导入，Then 回执显示 8 人成功、3 人标注"新建账号"，且 3 名新生成 `user(role=STUDENT)` + `student` 记录、`is_default_pwd=1`。
- Given 导入行中学号与某教师 `username` 相同，When 导入，Then 该行失败回执原因="学号与既有账号冲突"，不触碰教师账号（r2-C2）。
- Given 学生忘密，When 其所在课题老师执行重置，Then 密码回默认、`is_default_pwd=1`、留痕可查；非在管老师请求 → 403（r2-C3）。
- Given 项目已带入某课程 20 人快照，When 之后该课程名单删了 2 人，Then 项目成员仍是 20 人（两不相欠）。
- Given 学生用学号+默认密码登录，When 登录成功，Then 被强制跳转到改密页（复用 `LoginPage.vue` 现有 isDefaultPwd 拦截），未改密前其他学生页面不可进；登录页提示文案改为"请输入工号/学号"（r2-C5）。
- 边缘：同一学号被两个老师先后导入 → `student_no` 唯一，第二次为 upsert 不重建账号。
- 空态：项目 0 成员时，成员页给"去导入名单/手动选人"两个入口，矩阵页显示灰底引导文案。

**设计触点**：屏=项目列表/项目详情-成员 Tab/学生导入对话框；组件=`ImportDialog` 复用、`el-table` 成员行（移出按钮）、学生选择器（检索+多选）；状态=导入进度/回执/部分失败。
**关联页面（Sitemap 代偿：真实路由）**：`/projects`（菜单「课题项目」，roles: TEACHER,ADMIN）、`/projects/:id`（详情=成员/任务/数据/进度四 Tab）。
**已生成的设计资产**：待生成（建议路径 `frontend/src/pages/project/ProjectPage.vue`、`ProjectDetailPage.vue`、`components/project/MemberImportDialog.vue`）。
**待澄清问题**：无。

### S2 任务派发—提交—验收闭环 ⭐关键假设 Story

**Persona**：李老师 + 张同学（双端）
**Job**：把口头派活变成状态机流转，验收成为完成度唯一锚点
**优先级**：P0　**关键假设标记**：⭐

**功能描述**：老师在项目内建任务（标题/说明/截止时间/可选关联一个数据集），一任务派一个学生，选多人时服务端复制成多条；学生开始→提交（文字说明 + 可选挂数据版本）→老师验收通过或驳回（附意见，驳回回"进行中"，重提生成新提交记录，历史保留）。状态机：`NOT_STARTED → IN_PROGRESS → SUBMITTED → ACCEPTED | REJECTED(→IN_PROGRESS)`。

**In Scope**：
- 状态机全流转 + 每次流转写 `notification`（type=`LAB_TASK`，`ref_url` 跳项目详情，复用未读角标）
- 逾期派生规则：**deadline < now 且状态 ∈ (未开始/进行中)** 才算逾期，验收慢不算学生逾期（Q4）
- **deadline/关键考核字段修改走字段级留痕：复用现有 `RevisionService` 追加式修订表（target_type=`LAB_TASK`），改一次 deadline 记一条 old/new（r2-B2）**
- 提交记录追加式（`lab_task_submission`），驳回后重提=新行

**Out of Scope**：任务依赖/里程碑/WBS（Q4 明确拒绝）；小组任务（用"派组长+备注第 N 组"模拟）；任务模板库。

**验收标准**：
- Given 老师把同一任务勾选 3 个学生，When 保存，Then 生成 3 条独立任务记录、3 个学生各收到一条通知，互不影响状态。
- Given 学生已提交（SUBMITTED），When 老师驳回并填意见，Then 任务回 IN_PROGRESS、学生收到含意见跳回的通知、该提交行保留且 `review_comment` 仅本人+项目归属老师+ADMIN 可见（Q6）。
- Given 任务过了 deadline 仍是 SUBMITTED 等待验收，When 查看矩阵，Then 该格不为红色（非学生过错）。
- Given 学生试图打开他人任务的提交详情，When 请求提交记录接口，Then 返回 403/字段裁剪（半透明在后端强制，不靠前端隐藏）。
- Given 老师把某逾期任务的 deadline 改晚，When 保存，Then 矩阵红格消失但修订记录可查到"谁、原值、新值、时间"（r2-B2）。
- 边缘：被派任务的学生被移出项目 → 其未完成任务置 CLOSED（不删、留痕），按 r2-B1 冻结口径从分母剔除。
- **待你确认的规则①**：已提交（含已验收）任务不可删，只能驳回后关闭；未提交任务老师可删（软删留痕）。

**设计触点**：屏=任务列表 Tab/建任务抽屉/提交弹窗/验收对话框；组件=`el-drawer` 表单、状态徽章（5 态 5 色）、提交历史时间线；状态=空列表、逾期红标、驳回红边提醒。
**关联页面**：`/projects/:id?tab=tasks`、学生端 `/my-tasks`。
**已生成的设计资产**：待生成（`components/project/TaskFormDrawer.vue`、`TaskSubmitDialog.vue`、`TaskReviewDialog.vue`）。
**待澄清问题**：规则① 待拍板。

### S3 量化进度：学生 × 任务热力矩阵

**Persona**：李老师
**Job**：一屏定位"谁、在哪件事、卡了几天"
**优先级**：P0

**功能描述**：项目详情页「进度」Tab 提供：顶部汇总条（总完成度% = 已验收/总数、逾期数、成员数）；主体为**学生×任务热力矩阵**（格色：绿=已验收、黄=进行中/待验收、红=逾期、灰=未开始）；行尾=该生完成率，列尾=该任务通过/总人数；全部数字与矩阵由**同一接口同一口径**产出（Q7）。

**In Scope**：
- `GET /projects/{id}/progress` 单端点返回汇总+矩阵+学生汇总（杜绝双口径）
- **分母冻结口径（r2-B1）：全部统计收口在一个 stats 方法；口径固定为"成员移出时其未完成任务置 CLOSED 并从分母剔除，已验收任务永久计入"——同一项目任一时点的历史百分比可复现**
- 学生行按完成率降序；点格子跳转对应任务详情
- 列表页行内迷你完成度条（复用 ① 同源统计的轻量版）

**Out of Scope**：燃尽图/周提交趋势/时间轴（二期，一期项目样本太少，图表是空壳——Q7）；学生端显示他人完成率排名（反指标，明确不做）。

**验收标准**：
- Given 项目 20 任务 8 学生，When 打开进度 Tab，Then 矩阵一次请求渲染，格子状态与任务列表逐一对得上，抽查 0 偏差。
- Given 某学生 0 个任务，Then 矩阵行显示"未分配任务"灰行，分母公式不出现除零。
- Given 老师同时开列表页和详情页，Then 两处完成度%一致（同源断言测试）。
- Given 某成员被移出且其 2 条未完成任务按口径置 CLOSED，When 查看矩阵与百分比，Then 分母剔除该 2 条、历史已验收数字不变、归档后再无漂移（r2-B1）。
- 边缘：任务全部未开始 → 汇总显示 0% 且空态文案引导"先派发任务"，矩阵不空白。

**设计触点**：屏=进度 Tab；组件=纯 CSS 格子矩阵（仿 `StatGridCard.vue` 方格阵列气质，不引 echarts——遵循 unit-skin/零音效规约）、状态色 token 复用；状态=hover 格子出 tooltip（任务名/截止/状态）。
**关联页面**：`/projects/:id?tab=progress`。
**已生成的设计资产**：待生成（`components/project/ProgressMatrix.vue`）。
**待澄清问题**：无。

### S4 实验数据共享与共同维护（文件级版本链）

**Persona**：师生双端
**Job**：数据不散落网盘、修改不互相覆盖、来源可审计
**优先级**：P0

**功能描述**：项目内建数据集（原始文件落盘登记），全员可见/可下载/可**上传新版本（v2/v3 只增不覆盖）**；CSV 流式只读预览、小体积 xlsx 限量预览；师生可在数据集/版本上评论；数据集级软删/改名为**创建者本人与项目归属老师**，版本级软删为**该版本上传者本人与老师**（Q5 + r2-B3）。

**In Scope**：
- `lab_dataset` + `lab_dataset_version` + `lab_comment`
- 私有下载接口（权限=项目成员；不走现有公开头像链路）
- **同名归属显式化（r2-C4）：上传同名数据集不自动挂链——弹框强制二选一"作为既有数据集 v(N+1) 上传 / 新建数据集"，杜绝重名并行链**
- **版本级软删（r2-B3）：版本上传者本人 + 项目归属老师可软删单个版本（修正 Q5 规则到版本粒度）；数据集级删改仍为创建者+老师**
- 上传大小限制与类型白名单（xlsx/csv/txt/图片/zip，默认单文件 ≤50MB，配置项）；**安全基线（r2-B6）：落盘文件名一律服务端 UUID 生成，原名仅存字段；下载 Content-Disposition 编码回原名；类型白名单按魔数校验，不信后缀**
- **预览能力口径（r2-B5）：CSV 走流式逐行截断预览；xlsx 仅 ≤2 万行才允许预览且用流式读（现有全量 `XSSFWorkbook` 不可用于大文件），超限返回"请下载后查看"**
- 提交任务时可把某数据版本挂为交付物（与 S2 打通）

**Out of Scope**：在线结构化编辑（二期评估）、数据清洗算子/工作台（本产品永久不做——Q5）。

**验收标准**：
- Given 学生 A 已建数据集 v1，When 学生 B 在项目内上传同名文件，Then 系统弹框列出"挂到 A 的数据集成 v2 / 新建数据集"两个选项，由 B 显式选择；不产生静默重名链（r2-C4）。
- Given 学生 B 误传了一个版本，When B 软删自己的版本 v2，Then 版本标记删除、v1 不受影响、操作留痕；学生 C 无权限（r2-B3）。
- Given 学生 C 试图删除学生 A 创建的数据集，When 调用删除接口，Then 403 且前端按钮不渲染（后端强制）。
- Given 预览一个 20 万行 CSV，When 请求预览，Then 流式返回前 N 行 + `truncated:true`（不整文件进内存）；Given 一个 5 万行 xlsx，Then 返回"超预览上限请下载"，进程内存无尖峰（r2-B5）。
- Given 文件名含 `../` 或 `";..` 的恶意上传，When 落盘与下载，Then 存储路径与响应头均不受用户输入影响（r2-B6 渗透用例）。
- 空态：项目无数据集 → 引导卡"导入第一批实验数据"。
- 边缘：文件在盘上丢失（运维级）→ 下载接口 404 专用文案，不 500。

**设计触点**：屏=数据 Tab（数据集卡片列表→版本链抽屉）；组件=上传条（含版本说明输入）、预览对话框（虚拟滚动表格）、评论侧栏；状态=上传中/失败重试/超类型灰置。
**关联页面**：`/projects/:id?tab=data`。
**已生成的设计资产**：待生成（`components/project/DatasetPanel.vue`、`VersionChainDrawer.vue`、`CsvPreviewDialog.vue`）。
**待澄清问题**：无。

## Section 6.5 — 批次三增补：两模块合并为统一「实验项目」（2026-09-20）

**背景**：「课题项目」与「实验项目」两个菜单条目在形式与性质上冲突——同一门课既有"实验目录"又有"课题工作空间"，老师需要两处维护、两套心智。经 M-Q1~Q9 拷问 + R1~R4 反诘定稿：**合并为一个模块，模块名沿用「实验项目」**，课题实体成为"承载目录的容器"。

**概念模型（父子关系）**

| 层 | 实体 | 说明 |
|---|---|---|
| 容器 | `lab_project` where `source=SYSTEM` | 每个**课程×学期**懒生成一个，默认名=课程名（可改，course/semester 锁定），生成瞬间把 `course_student` 全量快照为成员（`AUTO_SNAPSHOT`，此后名单变更不回写） |
| 目录 | `experiment` 行 | 挂在容器 `course_id` 下：新增/编辑/删除/Excel 导入/从上学期复制（按 **course_code 回溯**上学期课程行"，无数据则置灰） |
| 工作空间 | `lab_project` 的成员/任务/数据集/进度 | 即批次一交付的课题协作能力（任务派发—提交—验收、完成度矩阵、数据集版本链） |
| 自建课题 | `lab_project` where `source=USER` | 无课程绑定的独立课题（M-Q7 挂课收口：建/改接口不收 course/semester） |

**入口与导航**：菜单只剩一项「实验项目」（`/experiments`，ADMIN+TEACHER+STUDENT）；列表用 Segmented 三段「全部 / 课程课题 / 我的课题」（+ 课程徽标 + 搜索）；点进详情为容器的 Tab 区：**实验目录**（仅 SYSTEM，学生只读）/ 成员 / 任务 / 数据 / 进度。旧实验项目独立列表页**整体退役**，一切旧入口（课程页按钮、Dashboard 就绪度方格、通知）深链到对应容器 `?tab=catalog`。`/projects`、`/projects/:id` 重定向到新址。

**关键行为规则**：① 容器懒生成、幂等（并发双 ensure 只有一个容器）；② 容器不可删除（403）可归档；③ 生成即快照、名单后续变更不回写；④ 历史学期容器目录只读；⑤ 唯一编号：容器 `LP-YYYY-NNN`（存量迁移行 `LP-YYYY-S<课程ID>` 不参与流水）、目录行沿用课程号-学期-流水；⑥ 归档/ensure/快照带入均写 `operation_log` 可追溯；⑦ 管理员全局只读（r4）：入口在「课程管理」页头，读侧直通、写侧（含归档）一律 403。

**权限与可见性**：沿用 r2-H1 学生白名单（学生仅可达课题相关端点；`/semesters`、`/dicts`、`/nlq/**`、`/reports/**` 一律 403）；因此学生侧列表/目录页**按角色条件请求**，且目录「操作」列（含材料清单/AI 档案）仅教师可见。教师仅本人归属；**管理员（r4 收口）可见全校容器与课题但全局只读**——菜单无「实验项目」入口（统一入口在「课程管理」页头），页内无任何写按钮，后端写接口对 ADMIN 一律 403（读侧直通不变）。

**验收**：AC1~AC14（见《LTPMS_课题项目合并_需求拷问记录.md》§6）全部通过——HTTP 套件 23/23；报表一"合并前后逐格一致"以接口输出与直连 SQL 逐格比对复核（63/63 格）；报表一/报表二代码零改动。实测修掉两处联调缺陷：并发 ensure 幂等洞（REPEATABLE READ 需当前读回取）、`operation_log.ip` NOT NULL 致审计日志静默丢失。

**迁移与回滚**：`database/upgrade_20260920_unify_experiment.sql`（幂等可重放）+ `database/rollback_20260920_unify_experiment.sql`；军规：打标写入零例外、禁 UPDATE 存量行、不得触碰 `experiment` 表。

**本批不做（显式推迟）**：S4 按班带入（容器自动快照已覆盖主场景）、S6 评论；学生侧材料清单/AI 档案未放行（NLQ 白名单未含学生）。

**未列入本版的 Stories（Phase 2 存档）**：小组任务与分组管理（B 档）；数据集在线结构化编辑（B 档评估）；燃尽图/趋势图表；学生端个人成绩报表；跨项目学生汇总视图（"我给 8 个学生派的活都怎么样了"）；skill/模板化多课题复制。

## Section 8 — Release Approach

**推荐顺序（先测关键假设）**：
1. **批次一 = S1 + S2 + S3 + S5（同一版本发布，缺一不可闭环）**：直接压测关键假设（师生是否用系统干活）与验收锚点（完成度可信）。**r2 的 P0 修订（C1 学生落地、C2 撞号、C4 同名弹窗、B1 分母冻结、B5 预览口径）全部属批次一范围**；角色分支清单回归随批次一执行。

4. MVP 显式集合：**{S1, S2, S3, S5}** —— 能交付"30 分钟建组派活 + 一张可信矩阵"的最小价值闭环。

**上线考虑**：
